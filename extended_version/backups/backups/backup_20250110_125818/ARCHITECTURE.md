# Архитектура проекта Bitcoin Price Predictor

## 1. Общий обзор

Проект представляет собой систему сбора и анализа данных для предсказания цены Bitcoin. Система построена по модульному принципу, где каждый модуль отвечает за работу с определенным типом данных.

## 2. Основные компоненты

### 2.1 Сборщики данных

#### BlockchainDataCollector (blockchain_data_collector.py)
Отвечает за сбор данных с Blockchain.com API:
- **Рыночные данные**: цена, капитализация, объем торгов
- **Майнинг**: сложность, доход майнеров
- **Сеть**: транзакции, адреса, комиссии
- **Блокчейн**: размер блоков, UTXO, мемпул

Как работает:
1. При первом запуске собирает всю историю
2. При обновлении проверяет последнюю дату
3. Загружает только недостающие данные
4. Сохраняет в CSV-файлы по категориям

#### YahooFinanceCollector (yahoo_finance_collector.py)
Собирает данные о связанных активах:
- **Криптокомпании**: 
  - MSTR (MicroStrategy) - крупнейший корпоративный держатель BTC
  - COIN (Coinbase) - крупнейшая криптобиржа в США
  - MARA, RIOT - майнинговые компании
- **Индексы**: 
  - SPY (S&P 500) - общее состояние рынка
  - QQQ (NASDAQ) - технологический сектор
  - GLD (Gold) - сравнение с золотом
  - UUP (US Dollar) - корреляция с долларом

#### SentimentDataCollector (sentiment_data_collector.py)
Анализирует настроения рынка:
- Индекс страха и жадности (Fear & Greed Index)
- Автоматическое обновление ежедневных данных
- Заполнение пропущенных значений

### 2.2 Система хранения данных

#### Структура директорий:
```
data/
├── blockchain/      # Данные блокчейна
│   ├── market/     # Рыночные метрики
│   ├── network/    # Сетевые метрики
│   └── mining/     # Майнинг метрики
├── market_data/    # Данные Yahoo Finance
└── sentiment/      # Данные о настроениях
```

#### Формат данных:
- CSV-файлы для удобства анализа
- Единый формат временных меток
- Проверка целостности данных

### 2.3 Координатор (historical_data_collector.py)

Главный модуль, который:
1. Инициализирует все сборщики
2. Координирует процесс обновления
3. Обрабатывает ошибки
4. Ведет логирование

## 3. Процессы и взаимодействия

### 3.1 Сбор данных
1. Запуск `historical_data_collector.py`
2. Проверка последних дат в файлах
3. Параллельный запуск сборщиков
4. Сохранение новых данных
5. Логирование результатов

### 3.2 Обработка ошибок
- Повторные попытки при сбоях API
- Пропуск недоступных метрик
- Заполнение пропусков в данных
- Подробное логирование ошибок

### 3.3 Резервное копирование
- Автоматическое создание бэкапов
- Сохранение всех типов данных
- Архивация с временной меткой
